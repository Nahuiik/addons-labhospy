1. Requerimiento Técnico

1.1. Alcance y objetivos

1.1.1. Objetivo general

Desarrollar un módulo para Odoo 19 que permita integrar Odoo con Microsoft Power BI, replicando y mejorando las funcionalidades de un conector previo (ej. Odoo 14) y adaptando la implementación a la arquitectura y API de Odoo 19.

1.1.2. Objetivos específicos

  • Configurar y probar una conexión segura con Power BI (Azure AD / OAuth2).
  • Administrar Workspaces, Datasets, Tablas y Columnas de Power BI desde Odoo.
  • Exportar datos de cualquier modelo de Odoo hacia tablas de Power BI.
  • Soportar exportación manual y automática (via cron).
  • Implementar sincronización incremental basada en create_date y write_date.
  • Gestionar plantillas de tablas y clonado de configuraciones.
  • Implementar métricas de monitoreo, logs y alertas.
  • Garantizar seguridad, trazabilidad y auditoría de las operaciones.

1.2. Compatibilidad, dependencias y lineamientos

1.2.1. Versiones soportadas

  • Versión mínima: Odoo 19.0.
  • Ediciones: Community y/o Enterprise (a definir en implementación).

1.2.2. Dependencias Odoo

  • base
  • web
  • mail (para chatter y notificaciones)
  • queue_job o equivalente (opcional/recomendado para grandes volúmenes)

1.2.3. Dependencias externas

  • Conectividad HTTPS hacia Power BI REST API (https://api.powerbi.com/v1.0/myorg).
  • Autenticación vía Azure AD OAuth2:
    • Client ID
    • Client Secret
    • Tenant ID
    • Redirect URI

1.2.4. Estándares de código

  • Seguir guías oficiales de desarrollo de módulos para Odoo 19.
  • Utilizar la nueva API de modelos y vistas (OWL/QWeb donde aplique).
  • Incluir docstrings y comentarios en lógica de sincronización y llamadas a APIs.
  • Manejo robusto de excepciones en todas las interacciones con Power BI.

1.3. Arquitectura funcional y modelos de datos

1.3.1. Modelo de conexión Power BI (powerbi.connection)

Campos principales:

  • name (Char): Nombre de la conexión.
  • api_url (Char): URL de API Power BI (por defecto https://api.powerbi.com/v1.0/myorg).
  • auth_url (Char): URL de autorización Azure (https://login.microsoftonline.com).
  • username, password (opcional, si se usa modo MasterUser).
  • client_id, client_secret, tenant_id, redirect_uri.
  • access_token, refresh_token, token_expiration.
  • state (draft/connected/failed), active (solo una activa).

Comportamiento:

  • Solo una conexión activa a la vez.
  • Botón “Probar Conexión”:
    • Solicita token a Azure.
    • Realiza llamada de prueba a Power BI (ej. listar workspaces).
    • Actualiza estado y mensajes de resultado.

1.3.2. Parámetros globales (res.config.settings)

Definidos como parámetros en ir.config_parameter (ejemplos):

  • powerbi_default_batch_size (ej. 10,000).
  • powerbi_default_cron_mode (incremental/full).
  • powerbi_use_write_date_default (boolean).
  • powerbi_slow_export_threshold (segundos, ej. 120).
  • powerbi_low_record_threshold (ej. 10).
  • powerbi_preview_limit (ej. 100 filas).
  • powerbi_token_expiration_buffer (ej. 300 segundos).
  • powerbi_alert_window_hours (ej. 24 horas).
  • powerbi_enable_auto_alerts, powerbi_show_advanced_alerts.

1.3.3. Workspaces (powerbi.workspace)

  • name, is_default, user_id, contadores de datasets/reports/dashboards.
  • Sincronización desde Power BI por medio de la conexión activa.

1.3.4. Datasets (powerbi.dataset)

  • name, type (permanent/temporary), workspace_id.
  • pbi_dataset_id, state (draft/published).
  • Lista de tablas relacionadas (table_ids).
  • Acción “Publicar” que crea el dataset en Power BI.

1.3.5. Tablas (powerbi.table)

  • name, dataset_id, model_id (ir.model), domain.
  • use_cron, cron_mode (incremental/full), batch_size.
  • last_sync_datetime, last_cron_run, last_sync_state.
  • force_full_export_next_run.
  • Relación de campos (field_ids – modelo powerbi.table.field).

Lógica principal:

  • Exportación incremental: filtra por create_date / write_date > last_sync_datetime.
  • Exportación full: ignora last_sync_datetime y exporta todo el dominio.
  • Procesamiento en lotes según batch_size.
  • Actualiza last_sync_datetime solo si la exportación completa es exitosa.

1.3.6. Columnas (powerbi.table.field)

  • table_id (tabla), field_id (ir.model.fields).
  • name (nombre en Power BI), ttype (tipo técnico), export (boolean).
  • relation_child_field_id: campo hijo para relacionales.
  • Conversiones de tipo:
    • Numéricos → número real.
    • Relacionales → valor de relation_child_field_id (ej. name).
    • Fechas → ISO 8601.

1.3.7. Plantillas de tablas (powerbi.table.template)

  • Permiten guardar la configuración completa de una tabla (modelo, campos, dominio, batch, etc.).
  • Botón “Guardar como plantilla” en la tabla.
  • Wizard “Crear desde plantilla” para generar nuevas tablas basadas en plantillas.

1.3.8. Métricas (powerbi.metric)

  • Registro por exportación: nombre, tipo de métrica, fecha, tabla, valor, estado, detalles.
  • Utilizado para monitoreo y generación de alertas.

1.3.9. Alertas (powerbi.alert)

  • Alertas automáticas basadas en umbrales globales.
  • Alertas personalizadas (si está habilitado el menú avanzado).
  • Tipos: exportación lenta, bajo número de registros, error de exportación, error de conexión.
  • Métodos: evaluación y notificación (chatter, email, notificación interna).

1.3.10. Logs de sincronización (powerbi.sync.log)

  • Registro por operación: tabla, modelo, res_id, operación, fecha, estado, mensaje.
  • Permite auditoría y trazabilidad fina de exportaciones.

1.4. Procesos clave

1.4.1. Exportación manual

  1. Desde el formulario de una tabla, el usuario hace clic en “Exportar datos”.
  2. El sistema valida conexión, dataset publicado y configuración de campos.
  3. Determina modo incremental/full según last_sync_datetime y configuración.
  4. Obtiene el conjunto de registros, los procesa en lotes, envía a Power BI.
  5. Registra métricas y logs.
  6. Actualiza last_sync_datetime y estado de sincronización.

1.4.2. Exportación automática (cron)

  • Se define un ir.cron para ejecutar una función global de sincronización.
  • Esa función localiza tablas con use_cron = True y llama al proceso de exportación.
  • Respeta el cron_mode por tabla.
  • Registra métricas, logs y alertas correspondientes.

1.4.3. Server Actions

  • Botón “Add Server Action” en una tabla:
    • Crea una acción de servidor ligada al modelo origen (ej. res.partner).
    • Agrega opción “Export To Power BI” en el menú de acciones de la vista del modelo.
  • Botón “Delete Server Action” elimina la acción asociada.

1.5. Seguridad y permisos

1.5.1. Grupos de usuarios

  • Power BI User: Lectura de objetos asignados.
  • Power BI Officer: Crear/editar datasets, tablas, plantillas; lanzar exportaciones manuales.
  • Power BI Manager: Configurar conexión, parámetros globales, cron, alertas, acceso total.

1.5.2. Record rules

  • Los usuarios no administradores solo ven registros donde sean responsables o participantes.
  • Los managers ven todos los registros sin restricción.

1.6. Rendimiento y robustez

  • Uso de procesamiento por lotes configurables.
  • Soporte opcional para colas de trabajo (queue_job).
  • Manejo de reintentos ante errores de red (política a definir).
  • Logs y métricas detalladas para diagnóstico.

1.7. Migración y compatibilidad

  • Si hay datos de un módulo previo (ej. Odoo 14), se recomienda un script de migración.
  • Mapeo de tablas, datasets, plantillas y fechas de sincronización cuando aplique.

1.8. Pruebas y validación

  • Pruebas unitarias de lógica de selección incremental, dominios, batching.
  • Pruebas de integración: flujo completo conexión → workspace → dataset → tabla → exportación.
  • Pruebas de seguridad: control de acceso, protección de credenciales y tokens.
  • Pruebas de rendimiento y regresión con grandes volúmenes de datos.

2. Software Requirements Specification (SRS)

2.1. Introducción

2.1.1. Propósito del documento

Este SRS define de forma estructurada los requisitos del módulo Power BI Connector para Odoo 19. Servirá como referencia para el equipo de desarrollo, QA y stakeholders durante todo el ciclo de vida del proyecto.

2.1.2. Alcance del sistema

El sistema será un módulo de Odoo que permita la integración con Microsoft Power BI, incluyendo configuración, administración de entidades Power BI (workspaces, datasets, tablas), exportación de datos, monitoreo y mecanismos de seguridad.

2.1.3. Definiciones y acrónimos

  • PBI: Power BI.
  • API REST: Interfaz HTTP de Power BI.
  • Workspace: Espacio de trabajo en Power BI.
  • Dataset: Conjunto de tablas en Power BI.
  • Tabla PBI: Tabla dentro de un dataset.
  • Sincronización incremental: Exportación basada en fechas de creación/modificación.
  • Cron: Tareas programadas en Odoo.

2.2. Descripción general

2.2.1. Perspectiva del producto

El módulo se integra como un componente adicional de Odoo 19, usando modelos, vistas, acciones de servidor, parámetros de sistema y tareas programadas. La interacción con Power BI será vía API REST y Azure AD OAuth2.

2.2.2. Funciones del sistema

  • Configurar y probar la conexión a Power BI.
  • Importar y administrar workspaces.
  • Crear, publicar y administrar datasets.
  • Definir tablas de exportación asociadas a modelos de Odoo.
  • Exportar datos de forma manual y automática (cron).
  • Soportar exportación incremental y full.
  • Gestionar plantillas de tablas y clonado.
  • Registrar métricas, logs y alertas.
  • Mostrar un monitor de salud en tiempo real del conector (estado de conexión, cron, métricas recientes).
  • Mantener un historial versionado de datasets/tablas para comparar y restaurar configuraciones.

2.2.3. Usuarios del sistema

  • Power BI Manager: administra conexión, parámetros, cron y alertas.
  • Power BI Officer: diseña datasets/tablas, lanza exportaciones manuales.
  • Power BI User: consulta los datos exportados.

2.3. Requisitos funcionales

RF-01: Configuración de conexión Power BI

  • El sistema debe permitir registrar credenciales Azure AD.
  • Debe incluir botón para probar conexión.
  • Debe validar y refrescar tokens de acceso.
  • Solo una conexión puede estar activa.

RF-02: Administración de Workspaces

  • Debe poder importarlos desde Power BI.
  • Debe mostrar metadatos básicos (nombre, tipo, contadores).
  • Debe permitir asignar un responsable Odoo a cada workspace.

RF-03: Administración de Datasets

  • Crear datasets desde Odoo, vinculándolos a un workspace.
  • Clasificarlos en permanente/temporal.
  • Publicarlos/crearlos en Power BI.
  • Actualizar su esquema cuando cambien las tablas relacionadas.

RF-04: Administración de Tablas

  • Definir tabla asociada a un modelo de Odoo y a un dataset.
  • Configurar dominio de filtro.
  • Elegir modo de exportación (full/incremental).
  • Configuración de batch size por tabla.
  • Definir columnas y tipos de datos exportados.

RF-05: Exportación de datos

  • Permitir exportación manual desde el formulario de tabla.
  • Permitir exportación automática mediante cron.
  • Procesar datos en lotes.
  • Generar métricas y logs.
  • Actualizar estado de sincronización y fecha de última exportación.

RF-06: Sincronización incremental

  • Filtrar registros nuevos y modificados con base en create_date y write_date.
  • Configurar opcionalmente si se usará write_date.
  • No reexportar registros sin cambios en modo incremental.

RF-07: Server Actions

  • Crear acciones de servidor asociadas a modelos de Odoo para exportar registros seleccionados a Power BI.
  • Permitir eliminar esas acciones desde la tabla.

RF-08: Plantillas

  • Guardar la configuración de una tabla como plantilla.
  • Crear tablas desde una plantilla mediante wizard.
  • Clonar tablas existentes.

RF-09: Monitoreo, métricas y alertas

  • Registrar métricas de cada exportación (duración, número de registros, estado).
  • Generar alertas automáticas basadas en umbrales definidos.
  • Soportar alertas personalizadas, opcionalmente, por tabla/dataset.

RF-10: Logs de sincronización

  • Registrar cada operación de sincronización con detalles por registro o lote.
  • Permitir su consulta y filtrado por modelo, tabla, fecha, estado.

RF-11: Monitor de salud en tiempo real

  • Proveer un tablero con indicadores de conexión, ejecución de cron, últimas exportaciones y errores.
  • Actualizar la información sin recargar totalmente la vista (polling ligero u OWL component).
  • Permitir filtrar por compañía, workspace o dataset para aislar incidentes.

RF-12: Gestión de versionado de datasets/tablas

  • Guardar snapshots del esquema de datasets y tablas (campos, tipos, dominios) cada vez que se publica un cambio.
  • Comparar versiones para identificar campos agregados/eliminados.
  • Restaurar una versión previa bajo confirmación del usuario.

2.4. Requisitos no funcionales

RNF-01: Rendimiento

  • Soportar al menos 50k registros por tabla por proceso de exportación.
  • Uso de procesamiento por lotes configurables.
  • Posibilidad de integración con colas de trabajo para paralelismo.

RNF-02: Seguridad

  • Almacenar credenciales de forma segura (cifrado / campos protegidos).
  • No registrar tokens en texto plano en logs.
  • Cumplir políticas de Azure OAuth2 para gestión de tokens.

RNF-03: Usabilidad

  • Vistas organizadas por menús lógicos: Conexión, Espacios de trabajo, Datasets, Tablas, Plantillas, Monitoreo, Reportes.
  • Mensajes de error y éxito claros y orientados al usuario funcional.

RNF-04: Disponibilidad

  • Exportaciones automáticas vía cron no deben requerir interacción del usuario.
  • En caso de fallos de red, el sistema debe registrar el error y permitir reintentos.

2.5. Restricciones

  • Diseñado específicamente para Odoo 19.
  • No se permite modificar el código core de Odoo.
  • Requiere que la instancia de Odoo tenga acceso HTTPS hacia Internet (Power BI).

2.6. Criterios de aceptación

  • Se puede conectar a Azure AD y listar workspaces correctamente.
  • Se puede crear un dataset desde Odoo y visualizarlo en Power BI.
  • Se puede crear una tabla, añadir campos y exportar datos exitosamente.
  • La sincronización incremental respeta last_sync_datetime y solo envía registros nuevos/modificados.
  • El cron actualiza datasets y reportes sin intervención manual.
  • Las alertas se generan y notifican correctamente a los usuarios configurados.
  • Es posible usar plantillas de tablas para configurar nuevas exportaciones más rápido.

3. Historias de Usuario

Épica 1: Configuración de conexión

US-01 – Registrar conexión Power BI

Como Administrador Power BI
Quiero configurar las credenciales de Azure AD y Power BI en Odoo
Para poder conectar la instancia de Odoo con Power BI de forma segura.

Criterios de aceptación:

  • Solo un usuario con rol Manager puede acceder a la pantalla de conexión.
  • La pantalla permite definir Client ID, Client Secret, Tenant ID, Redirect URI y URLs base.
  • Al pulsar “Probar Conexión”:
    • Si la conexión es válida, se muestra mensaje de éxito y estado “connected”.
    • Si falla, se muestra mensaje de error claro y el estado queda en “failed”.

US-02 – Una sola conexión activa

Como Administrador
Quiero que solo exista una conexión activa a Power BI
Para evitar inconsistencias entre múltiples configuraciones.

  • Al activar una conexión, las demás conexiones se desactivan automáticamente.
  • Si no hay ninguna conexión activa, el sistema debe bloquear exportaciones y mostrar aviso.

Épica 2: Workspaces y Datasets

US-03 – Importar Workspaces

Como Analista
Quiero importar los Workspaces de Power BI a Odoo
Para administrarlos desde Odoo y vincular datasets/tablas.

  • Botón “Importar Workspaces” disponible cuando la conexión está activa.
  • La importación crea o actualiza registros de workspaces en Odoo.
  • Se muestra mensaje con el número de workspaces importados.

US-04 – Crear Dataset desde Odoo

Como Analista
Quiero crear datasets (permanentes o temporales) desde Odoo
Para organizar mis fuentes de datos en Power BI.

  • En la vista de Datasets se puede crear un nuevo dataset con nombre, tipo y workspace.
  • Botón “Publicar” lo crea en Power BI y guarda el pbi_dataset_id.
  • El tipo de dataset se muestra en la lista y kanban de Datasets.

Épica 3: Tablas y Columnas

US-05 – Configurar tabla de exportación

Como Analista
Quiero definir una tabla asociada a un modelo de Odoo y seleccionar campos
Para exportar datos de ese modelo a Power BI.

  • Se puede seleccionar el dataset, el modelo Odoo, el dominio y el batch size.
  • Se pueden añadir columnas seleccionando campos de ir.model.fields.
  • El nombre de columna en Power BI se puede editar (por defecto la descripción del campo).

US-06 – Configurar campos relacionales

Como Analista
Quiero configurar qué valor enviar para campos relacionales
Para tener datos legibles en Power BI.

  • Para many2one se puede elegir el campo hijo (ej. name) para exportar.
  • Para one2many y many2many se usa un formato estandarizado (ej. lista separada por comas o JSON).
  • Si no se configura el campo hijo, se tomará name por defecto (cuando exista).

Épica 4: Exportación y sincronización

US-07 – Exportar datos manualmente

Como Analista
Quiero ejecutar una exportación manual de una tabla
Para probar la configuración y desencadenar actualizaciones puntuales.

  • El botón “Exportar datos” valida la conexión, dataset y columnas configuradas.
  • Si no hay registros que cumplan el dominio, se muestra mensaje y estado “no_data”.
  • Si la exportación es exitosa, se actualiza last_sync_datetime y se genera una métrica.

US-08 – Sincronización incremental

Como Administrador
Quiero que las exportaciones automáticas sean incrementales
Para reducir el tiempo de ejecución y uso de ancho de banda.

  • El modo incremental exporta solo registros con create_date o write_date posteriores a last_sync_datetime.
  • El uso de write_date es configurable globalmente.
  • Los registros no modificados no se vuelven a exportar.

US-09 – Exportación automática vía cron

Como Administrador
Quiero programar exportaciones automáticas
Para mantener los datasets de Power BI actualizados sin intervención manual.

  • Cada tabla tiene bandera “Exportar usando cron” y un modo cron_mode.
  • El cron global recorre solo tablas con use_cron = True.
  • Se registran métricas y logs en cada ejecución.

Épica 5: Plantillas y clonado

US-10 – Guardar tabla como plantilla

Como Analista
Quiero guardar una tabla como plantilla
Para reutilizar la configuración en futuros proyectos.

  • Un botón “Guardar como plantilla” guarda modelo, campos, dominio, batch size y modo de exportación.
  • La plantilla registra cuántas veces se ha utilizado.

US-11 – Crear tabla desde plantilla

Como Analista
Quiero crear tablas a partir de plantillas
Para acelerar la configuración de nuevas conexiones de datos.

  • Wizard “Crear desde plantilla” permite elegir la plantilla y el dataset destino.
  • El usuario puede ajustar el nombre de la tabla antes de guardarla.

Épica 6: Monitoreo, alertas y trazabilidad

US-12 – Ver métricas de exportación

Como Administrador
Quiero ver métricas de cada exportación
Para evaluar rendimiento, tiempos de ejecución y volumen de datos.

  • La vista de métricas muestra tabla, fecha, duración, registros exportados y estado.
  • Se pueden filtrar métricas por tabla, estado y rango de fechas.

US-13 – Alertas automáticas

Como Administrador
Quiero recibir alertas cuando haya problemas en exportaciones
Para reaccionar rápidamente ante errores o anomalías.

  • Si una exportación falla, se genera una alerta crítica.
  • Si una exportación tarda más que el umbral configurado, se genera alerta de exportación lenta.
  • Las alertas se notifican por chatter y/o correo según configuración.

US-14 – Ver trazabilidad de sincronizaciones

Como Analista
Quiero ver el historial de exportaciones por registro/tablas
Para auditar qué datos se enviaron y cuándo.

  • Vista de logs muestra modelo, registro, fecha, operación y mensaje.
  • Permite filtrar por tabla, modelo, ID de registro y fechas.

Épica 7: Monitor de salud en tiempo real

US-15 – Consultar el estado del conector en vivo

Como Administrador Power BI
Quiero visualizar un panel con el estado actual del conector
Para detectar incidentes sin revisar cada tabla manualmente.

  • El panel muestra indicadores de conexión, último cron, tablas con errores y métricas recientes.
  • La información se actualiza automáticamente cada cierto intervalo.
  • Se pueden aplicar filtros por compañía, workspace o dataset.

Épica 8: Versionado de datasets y tablas

US-16 – Restaurar versión previa de un dataset/tabla

Como Power BI Officer
Quiero revisar las versiones anteriores de un dataset/tabla y restaurar una si es necesario
Para revertir cambios que hayan roto exportaciones o dashboards.

  • Cada publicación de esquema genera una versión con fecha, usuario y resumen de cambios.
  • La interfaz permite comparar dos versiones y ver campos agregados/eliminados.
  • Restaurar requiere confirmación y registra una nota en el chatter de la tabla/dataset.

5.5. Cron y Server Actions

5.5.1. Cron global

  • Definido en ir_cron.xml.
  • Modelo: powerbi.table, método: _cron_export_tables.
  • Frecuencia configurable (ej. cada 15 minutos o según necesidad).
  • Método _cron_export_tables:
    • Busca tablas con use_cron = True.
    • Llama a export_table() para cada una, respetando su cron_mode.
    • Maneja excepciones para que el fallo de una tabla no detenga las demás.

5.5.2. Server Actions

  • Se crean dinámicamente desde botón en powerbi.table.
  • Se añaden al menú “Acción” de la vista tree/form del modelo origen (ej. res.partner).
  • La acción ejecuta exportación para los registros seleccionados en esa vista.

5.6. Logs, métricas y alertas

  • PowerBiMetric: registra métricas de alto nivel por exportación (duración, tamaño, estado).
  • PowerBiSyncLog: guarda trazabilidad detallada por lote o por registro.
  • PowerBiAlert: se evalúa posterior a cada exportación para decidir si crear alertas.
  • Las alertas se plasman en:
    • Chatter de la tabla/dataset.
    • Notificaciones internas.
    • Correo electrónico a los usuarios configurados, si procede.

5.7. Estrategia de pruebas

5.7.1. Pruebas unitarias

  • Test de obtención/renovación de tokens (con mocks de respuestas de Azure).
  • Test de selección incremental de registros según create_date/write_date.
  • Test de construcción de payload para diferentes tipos de campos.
  • Test de actualización de métricas y logs.

5.7.2. Pruebas de integración

  • Caso completo: conexión → importación de workspaces → creación/publicación de dataset → creación de tabla → exportación → ver datos en Power BI.
  • Caso de exportación incremental posterior con registros nuevos y modificados.

5.7.3. Pruebas de seguridad

  • Verificar que solo usuarios autorizados pueden alterar conexión y parámetros.
  • Asegurar que los tokens no se exponen en registros ni errores visibles.

5.7.4. Pruebas de rendimiento

  • Exportar grandes volúmenes (50k+ registros) para medir tiempos y estabilidad.
  • Ajustar batch size y, opcionalmente, cola de trabajos para optimizar.

5.8. Monitor de salud en tiempo real

  • Vista OWL dedicada que consulta un endpoint JSON (controlador) cada 30-60 segundos.
  • Datos mostrados: estado de la conexión activa, último resultado del cron, tablas con errores recientes, métricas agregadas (éxitos/fallos en última hora) y colas pendientes.
  • Backend: método en powerbi.table y powerbi.metric que arma el payload, aplicando filtros por compañía/workspace recibidos desde la UI.
  • Alertas rápidas: si se detecta error crítico, el panel muestra badge rojo y enlace directo a la tabla.

5.9. Gestión de versionado de datasets/tablas

  • Nuevo modelo powerbi.schema.version con campos:
    • resource_type (dataset/table), resource_id.
    • version_number, summary, diff_json, snapshot_payload.
    • changed_by, changed_on.
  • Triggers en write() de powerbi.dataset y powerbi.table para generar la versión cuando cambien campos de esquema (columnas, dominios, estrategia de sync).
  • Wizard “Comparar versiones” que muestra diferencias resaltadas y permite restaurar, creando un registro de auditoría.
  • Las restauraciones bloquean la exportación hasta que se verifique la consistencia y se vuelve a publicar el dataset.

B.2. Pseudo-código detallado

Método export_table(table, mode)

def export_table(table, mode):
    """
    Exporta los registros de una tabla Odoo hacia Power BI, respetando
    la estrategia de sincronización y el modo (incremental o full).
    """

    conn = get_active_powerbi_connection()
    dataset_id = table.dataset_id.pbi_dataset_id
    table_name = table.pbi_table_name
    fields = table.field_ids

    # 1) Determinar registros a exportar
    if mode == 'incremental':
        records = fetch_records_incremental(table)
    elif mode == 'full':
        records = fetch_records_full(table)
    else:
        # modo auto: decidir según configuración / last_sync
        records = fetch_records_auto(table)

    if not records:
        log_no_data(table)
        update_sync_metadata(table, state="no_data")
        return

    # 2) Procesar por lotes
    batch_size = table.batch_size or get_default_batch_size()
    record_batches = split_into_batches(records, batch_size)

    total_exported = 0
    started_at = now()

    # Si es estrategia snapshot_full, borramos filas primero
    if table.sync_strategy == 'snapshot_full':
        api_delete_rows(conn, dataset_id, table_name)

    for batch in record_batches:
        payload_rows = []
        for rec in batch:
            row = convert_record_to_pbi_row(rec, fields)
            payload_rows.append(row)

        payload = {"rows": payload_rows}

        # 3) Llamada al API
        api_post_rows(conn, dataset_id, table_name, payload)

        # 4) Métricas por lote
        total_exported += len(batch)
        metric_batch_success(table, len(batch))

    duration = (now() - started_at).total_seconds()

    # 5) Actualizar metadatos de sincronización
    update_sync_metadata(
        table,
        state="success",
        last_sync_datetime=now(),
        duration=duration,
        record_count=total_exported
    )

Método _cron_export_tables()

def _cron_export_tables():
    """
    Tarea programada que exporta todas las tablas marcadas para cron.
    Maneja errores por tabla sin detener todo el proceso.
    """

    tables = env['powerbi.table'].search([('use_cron', '=', True)])

    for table in tables:
        try:
            mode = table.cron_mode or 'incremental'
            export_table(table, mode)
        except Exception as e:
            # Registrar error y generar alerta
            log_export_error(table, e)
            create_powerbi_alert(
                table=table,
                alert_type="export_failed",
                message=str(e)
            )
            # Continuar con la siguiente tabla
            continue

C.1. Mapeo Odoo → Power BI (ejemplo facturas)

Modelo Odoo Campo Odoo Tipo Odoo Campo PBI Tipo PBI Regla de transformación
account.move id Integer id Int64 Directo
account.move name Char numero string Directo
account.move state Selection state string Directo (mismo valor técnico)
account.move amount_total Monetary amount_total double Convertir a float; manejar null como 0.0 o null

C.2. Reglas de transformación generales

  • Fechas: convertir a formato ISO YYYY-MM-DDTHH:MM:SSZ.
  • Monetary / Float / Integer: enviar como numérico real, nunca como string.
  • Boolean: mapear a true / false.
  • Many2one: usar relation_child_field_id (típicamente name).
  • Many2many / One2many: decidir formato:
    • Lista separada por comas (texto).
    • JSON (texto) si se necesita estructura.
  • Nulls: respetar null en Power BI siempre que el tipo lo permita.

C.3. Estrategia de migración desde versiones anteriores

  1. Exportar registros de modelos antiguos (powerbi.table, powerbi.dataset) en Odoo 14/15.
  2. Normalizar y limpiar:
    • Dominios de búsqueda en texto.
    • Campos renombrados entre versiones de Odoo.
  3. Importar en Odoo 19:
    • Crear nuevas tablas con esquema actualizado.
    • Mapear IDs de datasets y workspaces si se reutilizan.
  4. Regenerar server actions y revisar cron jobs.
